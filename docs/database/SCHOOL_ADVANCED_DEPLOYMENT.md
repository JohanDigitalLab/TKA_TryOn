## Validasi PostgreSQL offline (24 November 2026)

Instalasi dependensi opsional hanya di [sandbox lokal](../../.local/school-sql-sandbox), tanpa mengubah [manifest aplikasi](../../package.json) atau [lockfile aplikasi](../../package-lock.json).

- Baseline sintetis dibangun dari snapshot ter-pin: 55 tabel publik, 465 kolom beserta default/identity, 268 constraint, indeks, 108 fungsi historis, ACL efektif anon/authenticated, 25 policy dan 30 trigger. Tidak memulihkan data asli, owner, default ACL, role inheritance, ataupun keseluruhan skema Auth.
- Mock eksplisit: tabel Auth minimal, role tanpa inheritance, serta fungsi UID yang membaca identitas fixture. Ini **bukan Supabase Auth/JWT/GoTrue/PostgREST**, bukan bukti RLS pengguna nyata atau parity versi PostgreSQL server.
- Pemeriksaan badan fungsi dimatikan **hanya saat restore fungsi historis snapshot** yang memiliki dependency historis belum terselesaikan; diaktifkan kembali sebelum migrasi final. Semua **26 fungsi migrasi** berhasil dibuat, seluruh preflight/hash/ACL/constraint tetap utuh, transaksi berhasil commit pada baseline sintetis kosong. Tiga approval hanya diubah di salinan memori untuk fixture; artefak final tetap menolak secara default.
- Bukti negatif: approval default ditolak tanpa kolom agenda tersisa; drift ACL tabel dan hilangnya indeks unik wajib masing-masing ditolak oleh preflight asli; instalasi ulang ditolak. Tidak ada preflight yang dihapus atau dipalsukan agar lolos.
- [Verifikasi katalog](verify-school-advanced.sql:1): seluruh **106 baris pemeriksaan ok bernilai true**.
- [Fixture eksekusi](../../tests/database/school-advanced-pglite.cjs:1): create/publish/list/start/resume/save/submit agenda dan tugas, workspace/ranking, skor pilihan tunggal 100, revisi kedaluwarsa, freeze konten/cohort, start terlalu awal, payload jawaban salah, dan penolakan aktor mock. Agenda aktif menggunakan fixture privileged tersendiri, bukan menggeser waktu agenda published melewati trigger.
- **Tidak ditemukan bug SQL final pada cakupan ini.** Kegagalan awal adalah kekurangan harness/fixture: identity belum didukung, indeks unik harus dipulihkan sebelum FK, grade seed wajib, membership admin otomatis dari trigger, dan format payload jawaban. ## Instalasi manual Supabase SQL Editor

1. **Staging terisolasi dahulu**, backup, salinan data yang telah disanitasi dan aktor dua sekolah. Reviewer membandingkan katalog aktual, owner fungsi security-definer, ACL termasuk hak warisan role, trigger/policy, indeks, dan penulis afiliasi/provisioning/konten dengan snapshot. Eksekutor wajib mempunyai ownership/izin penggantian fungsi dan lock tabel termasuk Auth. Jangan jalankan ulang migrasi historis untuk “memenuhi dependency”.
2. Review nyata pemetaan **school_uid → schools.id, bukan UID akun SCHOOL**. SQL memeriksa orphan, collision profil SCHOOL, duplikasi peserta, kelas lintas sekolah, profil orphan, serta konsistensi attempt tugas. Ketiadaan collision/orphan bukan bukti semantik pemetaan: persetujuan manusia tetap wajib. Bila gagal, HOLD; susun rekonsiliasi terpisah. Jangan menebak konfirmasi atau memberi membership otomatis.
3. Review seluruh penulis afiliasi (pembuatan/update siswa, operator, undangan, perpindahan, profil, membership, status sekolah/Auth, job/service-role/manual SQL). Setujui kebijakan scope dan lock order; hentikan penulis saat maintenance. Runtime memakai lock SHARE tabel afiliasi; throughput/deadlock/kompatibilitas penulis lama harus diuji. Paket tidak mengeraskan seluruh provisioning lama.
4. Buka **seluruh [deploy-school-advanced.sql](deploy-school-advanced.sql:1)** dalam satu SQL Editor query. **Hanya di blok HUMAN APPROVAL EDIT ZONE, baris 9–11**, ubah tiga literal false menjadi true setelah ketiga persetujuan nyata: [human_approved, mapping_approved, affiliation_writers_approved](deploy-school-advanced.sql:9). Default artefak tetap false dan selalu menolak instalasi tanpa edit eksplisit. Jangan mengedit gate internal blockers/agenda atau badan fungsi. Simpan salinan approval/evidence di proses deployment, bukan secret dalam repository.
5. Jalankan satu query lengkap secara manual. Satu BEGIN/COMMIT, dependency blockers dipasang sebelum gate agenda dalam transaksi yang sama. Timeout/constraint/drift/approval error membatalkan keseluruhan; bila SQL Editor mempertahankan sesi aborted, akhiri transaksi gagal dengan rollback manual sebelum pekerjaan lain. Tidak boleh melanjutkan hanya potongan akhir. Tidak ada pembersihan data, cascade, default tipe baru, atau validasi FK sejarah diam-diam.
6. **Non-idempoten:** rerun setelah sukses sengaja gagal pada baseline/schema/constraint yang sudah berubah. Kalau blockers sudah terpasang sendiri, atau backend drift, paket ini juga HOLD. Jangan memakai IF NOT EXISTS, melewati hash, menghapus constraint, atau menjalankan ulang sebagian fungsi. Perlu delta deployment baru yang direview. Setelah COMMIT, pemulihan bukan sekadar rollback transaksi: nonaktifkan penggunaan fitur melalui prosedur aplikasi yang disetujui, pertahankan attempt/jawaban/hasil, dan review forward-fix/restorasi definisi. Frontend existing auto-aktif saat capability lulus; rencanakan maintenance sebelum commit.

## Verifikasi wajib sesudah instalasi staging

- Jalankan **[verify-school-advanced.sql](verify-school-advanced.sql:1)** secara manual sebagai query terpisah. Transaksi read-only, security invoker (tidak membuat fungsi privileged), tanpa role switching atau klaim Auth palsu. Semua kolom **ok** harus true, bukan NULL. Cocokkan 26 fungsi (body hash, grants, search path, owner dan argument/result), sembilan constraint bernama, tujuh trigger, RLS, policy dan ACL tabel. Tujuh constraint baru sengaja NOT VALID; dua unik langsung tervalidasi. Tiga FK/check kolom inline juga ditampilkan/dapat diperiksa dari katalog; review definisi constraint, bukan hanya jumlah. Jangan memvalidasi constraint sebagai bagian query ini.
- Verifikasi katalog bukan uji autentikasi. Panggil ekspor [verifySchoolAdvancedCapability()](../../scripts/verify-school-advanced-capability.mjs:6) secara eksplisit dari harness staging tepercaya dengan dua client Supabase: client pengguna **yang sudah login sungguhan** dan client anon tanpa sesi, beserta ID sekolah sendiri dan sekolah lain yang diketahui ada. Client pengguna harus actor terverifikasi yang bukan anggota sekolah lain. Skrip memverifikasi user melalui Auth, kontrak positif sekolah sendiri, dan error 42501 untuk sekolah lain/anon; missing RPC/network bukan dianggap lolos. Tidak ada CLI, environment loader, auto-login atau token spoof. Skrip ini disediakan, **tidak dijalankan dalam pekerjaan offline ini**.
- Uji mutasi staging terpisah dengan aktor siswa/guru/admin A/B, managed tanpa mapping/membership, suspended/unverified, pencabutan affiliation; publish/cancel/stale revision, start/resume/save/submit paralel, deadline persis, durasi penuh, peserta palsu, snapshot/konten frozen, skor tiga tipe soal, regresi mandiri TRYOUT/EXERCISE dan larangan bocor kunci/tema/topik. Pencabutan akses/pembatalan menolak finalize; attempt tertinggal memerlukan keputusan administratif terpisah. Lihat juga [rencana staging](SCHOOL_STAGING_TESTS.md).
- Baru sesudah seluruh bukti staging lulus dan approval produksi tersendiri, ulangi review katalog/data/approval dan pemasangan manual pada produksi. Keberhasilan tes Node tidak menggantikan parser PostgreSQL, uji locking/RLS/security-definer, maupun staging. **Runtime, staging, dan produksi belum diverifikasi oleh pekerjaan ini.**
